# Migrating from 0.2.x to 0.3.0

## What changed

`seam build` now compiles TypeScript backends and restructures the `dist/` output:

| Path | 0.2.x | 0.3.0 |
|------|-------|-------|
| Frontend assets | `dist/client/` | `dist/client/` (unchanged) |
| Backend compiled entry | — (not built) | `dist/server/<entry-name>.js` |
| Prod manifest | `dist/_seam_prod.js` | `dist/server/_seam_prod.js` |

`seam start` now runs the compiled backend with `node` instead of the TypeScript source with `tsx`, as long as `seam build` has been run first.

## Required changes

### 1. Update `.gitignore`

If you committed a `dist/` ignore entry, no change is needed. If you had finer-grained ignore rules, make sure `dist/server/` is also ignored.

### 2. CI/CD deploy scripts

Any step that references `dist/_seam_prod.js` directly must be updated to `dist/server/_seam_prod.js`.

### 3. Custom `distDir` in wire env (advanced)

If you wrote a custom host adapter that reads `distDir` from the wire env and loads `_seam_prod.js` from it, no source change is needed — `seam build` and `seam start` now pass `dist/server/` as `distDir` automatically.

### 4. NestJS projects

The manifest location change applies to NestJS too. The NestJS compiled output path (controlled by `nest-cli.json`) is unchanged — only `_seam_prod.js` moves to `dist/server/`.

## Unchanged

- `seam dev` behavior is identical.
- `seam start` falls back to `tsx <original-entry>` if the compiled output is missing (e.g. when running `seam start` without `seam build` first, in development).
- All adapter APIs (`seam()`, `inlay`, `seamHost()`, `seamPort()`) are unchanged.
- `seam.config.ts` format is unchanged.
